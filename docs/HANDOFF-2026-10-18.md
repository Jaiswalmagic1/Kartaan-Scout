# Handoff — KARTAAN Scout Guided Research (2026-10-18)

## Goal
Build KARTAAN Scout into a guided marketplace listing research workspace, not merely a tool that captures one page and copies a prompt. For one product/SKU, it should collect visible seller-side and buyer-side evidence, ask the chosen LLM to identify gaps and next steps, and bring structured recommendations back to Scout for validation and seller approval.

## Current workbench state
The validated local build is v0.1.3. Its package includes the Manifest V3 extension, guided multi-page capture session, seller-side visible form/metric collection heuristics, buyer-side product/search/competitor capture, review capture for visibly loaded comments, local session state, CSV/JSON exports, prompt generation, response parsing/field allowlist, approval gate, tests and docs.

The runnable package was generated as a downloadable ZIP in the originating ChatGPT conversation. This handoff branch records the intent, workflow, constraints and validation results so later work can resume from a known state. Before publishing/merging a release, ensure the exact source package is also checked into the version-control tree and linked from the branch README.

## Intended workflow
1. One research session per listing/SKU.
2. Capture the logged-in supplier listing/edit/details page. Read only the visible DOM and visible form fields; never credentials or hidden API payloads.
3. Capture the buyer product page, relevant search results and competitor cards.
4. Capture review comments only after the user expands/paginates them and they are visible.
5. Copy one consolidated prompt with all captures, provenance, missing sources and conflicts into ChatGPT/Claude/Gemini.
6. LLM returns JSON containing summary, conflicts, limitations, `nextActions`, and allowlisted `proposals`.
7. The human follows `nextActions` by opening and capturing the requested sources; Scout does not navigate or crawl automatically.
8. Paste refreshed packet into the same LLM conversation, then paste the final JSON response back into Scout.
9. Scout validates schema/allowlist, displays rationale/evidence/conflicts, requires additional confirmation where flagged, and copies approved field values for manual entry.
10. Seller always performs final marketplace save/submit.

## Safety and data hygiene
Never add the user's original raw product capture or full listing identifiers to a public repo. Use anonymized fixtures. Do not use marketplace APIs, cookies/session tokens, hidden responses, remote crawling, credential collection, CAPTCHA solving or access-control bypass. No auto-submit/publish.
